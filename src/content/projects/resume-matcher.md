## 배경

이직 준비 중 이력서를 채용공고(JD)마다 매번 손으로 다듬는 게 번거로워서, AI와 대화하며 JD에 맞춰 이력서를 개선해주는 개인용 도구를 만들었습니다.

## 문제

"이 JD에 맞게 강점을 더 부각시켜줘" 같은 수정 요청에 AI가 응답할 때, 대화형 설명과 실제로 적용 가능한 수정본(전체 이력서 텍스트)을 구분해서 안정적으로 받아와야 했습니다. 프롬프트만으로 형식을 강제하면 AI가 부분 diff만 주거나 응답 포맷이 매번 흔들리는 문제가 있었습니다.

## 담당 범위

기획부터 백엔드 API, 프론트엔드까지 1인으로 설계·구현했습니다.

## 기술적 판단과 해결 방법

- **구조화된 출력(Structured Output).** Claude API의 `outputConfig`로 응답 스키마(`reply`, `updatedResume`)를 강제해, 파싱 실패나 형식 흔들림 없이 대화 코멘트와 수정본을 분리해 받습니다.
- **서버는 상태를 갖지 않는 프록시.** 이력서·JD·대화 기록은 브라우저 localStorage에만 저장하고, Spring Boot 백엔드는 DB·인증 없이 Claude API 호출만 중계합니다. 개인용 단일 사용자 도구라는 범위에 맞춰 불필요한 인프라를 걷어낸 선택입니다.
- **PDF 파싱 실패를 원인별로 구분.** PDFBox로 이력서 PDF에서 텍스트를 추출할 때 "파일 손상·미지원 형식"과 "스캔본이라 텍스트가 없음"을 별도 예외로 나눠, 사용자에게 원인에 맞는 메시지를 보여줍니다.

## 결과와 배운 점

현재는 개인적으로 이력서를 JD에 맞춰 다듬는 데 실제로 사용 중입니다. 프롬프트로 응답 포맷을 강제하려 애쓰는 것보다 구조화된 출력을 쓰는 편이 훨씬 안정적이었고, 개인용 도구는 DB·인증 같은 표준 구성 없이도 충분히 실용적으로 만들 수 있다는 걸 다시 확인했습니다.
