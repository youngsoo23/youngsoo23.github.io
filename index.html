Case Study — 01

Toggle 3.0: 레거시 PHP를 Spring Boot로 전면 리빌드

회사 오픈플랜주식회사 역할 백엔드 매니저 기간 2022.11 – 2025.06 도메인 여행자보험 플랫폼

문제

외주 PHP 기반으로 만들어진 레거시 보험 플랫폼(토글 1.0)은 신규 기능 개발조차 어려운 상태였습니다. 운영도 개발자 의존적이어서, 상품·계약·고객 정보를 바꾸는 단순 작업까지 하루 평균 10~20건씩 개발자 수작업으로 처리되고 있었습니다.

설계

사용자 서비스·운영 백오피스·파트너 백오피스 3개 축으로 플랫폼을 재설계하고, 세 서비스가 공통으로 쓰는 결제·인증·알림 기능은 별도의 인프라 레이어로 분리했습니다. 외부 기관 연동을 한 곳에 모아 장애·비용 리스크를 격리하는 것이 핵심 판단이었습니다.

서비스 레이어

사용자 서비스
보험 가입·결제 플로우, B2B2C(BBC) 플로우, 포인트 적립
운영 백오피스
상품·마케팅·고객·계약·제휴사 관리
파트너 백오피스
제휴사 직접 가입, 그룹 보험 플로우, 계약 관리

공통 플랫폼 · 인프라 레이어 (장애·비용 리스크 격리)

Payment
PortOne(IMPort) 연동, 승인·취소·환불, Webhook 상태 동기화
Internal
KCB·NICE 실명인증, 중복 요청 방지 로직
Notification
Naver Cloud 기반 SMS·알림톡·이메일 발송

핵심 결정

  • 결제 상태를 Webhook으로 비동기 동기화. PG 응답을 동기적으로 기다리지 않고, Webhook 수신 시점에 결제 상태를 반영해 사용자 서비스와 백오피스 양쪽에서 결제 도메인을 일관되게 유지했습니다.
  • 실명인증을 Internal 서비스로 집약. KCB·NICE 호출을 한 곳에 모으고 중복 요청 방지 로직을 넣어, 외부 기관 장애가 서비스 전체로 번지지 않도록 분리했습니다.
  • JPA + QueryDSL로 ORM 일관화. 레거시 PHP의 산발적인 쿼리 구조를 걷어내고, Liquibase로 스키마 변경 이력을 관리해 쿼리 복잡도와 유지보수 비용을 낮췄습니다.

성과

  • 백오피스 구축으로 하루 평균 10~20건의 운영 수작업 요청 제거, 개발자 개입 없이 운영 가능한 구조로 전환
  • 실명인증 호출을 공통 모듈로 통합해 인증 호출 비용 약 40% 절감
  • Slack 기반 장애 알림 자동화로 선제 대응 체계를 마련, 반복 CS 인입 약 50% 감소

Case Study — 02

Global MVP: Stripe·해외 보험사 API 연동으로 2개월 내 런칭

회사 오픈플랜주식회사 역할 백엔드 매니저 기간 2025.05 – 2025.09 도메인 해외 여행자보험 (싱가포르)

맥락

Stripe 결제와 Starr 보험사 API 연동을 중심으로 한 신규 글로벌 플랫폼이었습니다. MSA로 설계하는 대신, 해외 시장 반응을 빠르게 검증하기 위해 MVP 형태로 약 2개월 내 개발·런칭을 완료했습니다.

핵심 결정

  • Idempotency key 기반 요청 제어. Stripe PaymentIntent와 Starr 보험사 API(견적→심사→증권 발급) 통합 과정에서 idempotency key와 Webhook 비동기 검증 로직을 직접 설계해 중복 결제와 데이터 불일치를 해결했습니다.
  • Redis Cache-Aside로 반복 조회 제거. 국가·상품 조회 API의 DB 반복 호출을 캐싱으로 없애 동일 조건 기준 응답 지연을 약 30% 개선했습니다.
  • Slack Webhook 기반 장애 사전 탐지. 주요 API 지연·오류를 실시간으로 감지해 운영팀이 문제 발생 직후 대응할 수 있는 체계를 확보했습니다.
